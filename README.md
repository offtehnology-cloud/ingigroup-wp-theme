# IngiGroup WordPress Theme

Кастомная классическая тема WordPress для сайта инжиниринговой компании «ИНЖИГРУПП». Цель проекта — максимально близко воспроизвести внешний вид и поведение исходного сайта [ingigroup.ru](https://ingigroup.ru/), сохранив возможность редактировать контент через административную панель WordPress.

**Репозиторий:** <https://github.com/offtehnology-cloud/ingigroup-wp-theme>  
**Тестовый сайт:** <https://ingigroup.xyz/>  
**Основной сайт — визуальный ориентир:** <https://ingigroup.ru/>

> Тема содержит код оформления и логику WordPress. Контент сайта, записи проектов, медиабиблиотека и настройки WordPress хранятся в базе данных и каталоге `wp-content/uploads` конкретной установки и не входят в этот Git-репозиторий.

## Возможности

- Классическая PHP-тема WordPress без обязательного этапа сборки.
- Главная страница, составленная из повторно используемых частей шаблона.
- Адаптивная шапка, главное меню, меню услуг и мобильное меню-бургер.
- Секции услуг, преимуществ, сертификатов, отзывов, формы обратной связи и карты.
- Пользовательские типы записей для проектов, услуг, отзывов и сертификатов.
- Раздел реализованных проектов с тремя подразделами и отдельными страницами объектов.
- Метаполя проекта: регион, заказчик, список работ, дополнительные работы и галерея изображений.
- Настройки контактов, слогана, социальных ссылок и координат карты через Customizer WordPress.
- AJAX-отправка формы обратной связи через `wp-admin/admin-ajax.php`.
- Анимации появления элементов и эффекты для первого экрана.

## Требования

- Работающая установка WordPress.
- Сервер с PHP и базой данных, совместимыми с используемой версией WordPress.
- Доступ к файлам WordPress для установки темы.
- Для работы внешних ресурсов сайта — возможность загружать Google Fonts, библиотеки анимаций с CDN и скрипт Яндекс Карт.

В репозитории не зафиксированы минимальные версии WordPress и PHP. Перед установкой на рабочий сайт проверьте тему на тестовой копии с версиями WordPress и PHP, используемыми на целевом сервере.

Отдельные плагины и Node.js-сборщик для самой темы не требуются. jQuery используется из состава WordPress. Внешние JavaScript-библиотеки подключаются из CDN.

## Установка

### Вариант 1. Через Git

Откройте терминал в корневом каталоге WordPress и выполните:

```bash
cd wp-content/themes/
git clone https://github.com/offtehnology-cloud/ingigroup-wp-theme.git ingigroup
```

Убедитесь, что главный файл темы находится по пути:

```text
wp-content/themes/ingigroup/style.css
```

Если каталог `ingigroup` уже существует, не выполняйте `git clone` поверх него. Для обновления перейдите в каталог темы и сначала проверьте локальные изменения:

```bash
cd wp-content/themes/ingigroup
git status
git pull
```

Не используйте `git pull`, пока не сохраните собственные изменения и не убедитесь, что обновление не перезапишет нужные правки.

### Вариант 2. Через ZIP-архив GitHub

1. Откройте страницу репозитория.
2. Нажмите **Code → Download ZIP**.
3. Распакуйте архив.
4. Поместите содержимое папки темы в `wp-content/themes/ingigroup/`.
5. Проверьте, что `style.css` и `functions.php` лежат непосредственно в `ingigroup/`, а не во вложенной папке с названием вроде `ingigroup-wp-theme-main/`.

### Активация

1. Войдите в административную панель WordPress.
2. Откройте **Внешний вид → Темы**.
3. Выберите **IngiGroup** и нажмите **Активировать**.
4. Откройте **Настройки → Постоянные ссылки** и нажмите **Сохранить изменения**, даже если формат ссылок не менялся. Это обновит rewrite rules.
5. Проверьте главную страницу и страницы `/projects/` и `/services/`.

Перед активацией на рабочем сайте сделайте резервные копии базы данных, каталога `wp-content/uploads` и текущей темы. Само переключение темы не переносит записи, настройки или изображения с другого сайта.

## Первичная настройка WordPress

### Меню

В теме зарегистрированы следующие области меню:

| Область | Назначение |
|---|---|
| `primary` | Основное меню в шапке и мобильном меню |
| `services_menu` | Меню услуг в оранжевой полосе; также выводится в мобильном меню |
| `footer_services` | Ссылки на услуги в подвале |
| `footer_docs` | Ссылки на документы в подвале |

Создайте и назначьте меню через **Внешний вид → Меню** или соответствующий экран управления меню в вашей версии WordPress. Если выпадающие пункты в главном меню не появляются, проверьте вложенность пунктов и глубину, заданную в вызове `wp_nav_menu()`.

### Настройки контактов

Откройте **Внешний вид → Настроить → ИНЖИГРУПП — Контакты**. Доступны настройки:

- слоган в шапке;
- телефон;
- адрес электронной почты для заявок;
- основной и дополнительный адреса;
- ссылки на Telegram и WhatsApp;
- текст копирайта;
- широта и долгота для карты.

Большинство значений читается через `get_theme_mod()` с резервными значениями по умолчанию. После переноса на другой сайт проверьте все контакты, адреса и координаты: значения, введённые через Customizer, находятся в базе данных WordPress и не переносятся вместе с файлами темы.

### Контент и изображения

Загрузите нужные изображения в **Медиафайлы** WordPress и используйте их в записях или настройках темы. Если тема устанавливается на чистый сайт, записи проектов, отзывы, сертификаты и другие данные необходимо создать или перенести отдельно.

## Структура проекта

```text
ingigroup/
├── README.md                       # Документация проекта
├── ingigroup-handover-v2.md        # Дополнительный файл хендовера/истории разработки
├── style.css                       # Заголовок темы WordPress и стили корневой таблицы
├── functions.php                   # Подключение модулей темы
├── header.php                      # Шапка сайта, навигация, мобильное меню
├── footer.php                      # Подвал сайта
├── front-page.php                  # Главная страница
├── page.php                        # Шаблон обычной страницы
├── index.php                       # Резервный шаблон WordPress
├── archive-project.php             # Архив проектов: /projects/
├── taxonomy-project_category.php   # Страница категории проектов
├── single-project.php              # Детальная страница проекта
├── inc/
│   ├── setup.php                   # Возможности темы, меню и размеры изображений
│   ├── enqueue.php                 # Подключение CSS, JavaScript и CDN-зависимостей
│   ├── customizer.php              # Настройки контактов и карты
│   ├── cpt.php                     # Пользовательские типы записей, таксономия и URL
│   ├── meta-boxes.php               # Метаполя проекта и выбор изображений галереи
│   └── ajax-form.php               # Серверный обработчик формы обратной связи
├── template-parts/
│   ├── hero.php                    # Первый экран главной страницы
│   ├── services.php                # Секция услуг
│   ├── advantages.php              # Секция преимуществ
│   ├── certificates.php             # Секция сертификатов
│   ├── opinions.php                # Секция отзывов
│   ├── cta-form.php                # Форма обращения
│   ├── map.php                     # Адрес и контейнер карты
│   ├── breadcrumbs.php             # Хлебные крошки для раздела проектов
│   └── project-card.php            # Карточка проекта в списке
└── assets/
    ├── css/
    │   ├── main.css                # Основные стили и компоненты
    │   ├── responsive.css          # Адаптивные стили
    │   └── hotfix.css               # Последующие корректировки CSS
    ├── js/
    │   └── main.js                 # Меню, AJAX-форма, карта и анимации
    └── images/                     # Изображения темы, в том числе логотип
```

Роль основных файлов:

- `functions.php` задаёт константы `INGI_VERSION`, `INGI_DIR`, `INGI_URI` и подключает модули из `inc/`.
- `inc/setup.php` включает поддержку заголовка страницы, миниатюр, логотипа и HTML5, регистрирует меню и размеры изображений.
- `inc/enqueue.php` подключает ресурсы и формирует версии файлов по времени последнего изменения (`filemtime`), чтобы изменения CSS и JavaScript не застревали в браузерном кеше.
- `inc/cpt.php` регистрирует пользовательские типы записей и URL-маршруты.
- `inc/meta-boxes.php` добавляет поля данных объекта в редактор проекта.
- `template-parts/` предназначена для небольших повторно используемых частей разметки.

Сборщика CSS/JavaScript и обязательных файлов `package.json` или `composer.json` в текущей архитектуре нет. Ресурсы подключаются непосредственно из темы и CDN.

## Устройство раздела «Проекты»

Раздел реализован на пользовательском типе записей `project` и таксономии `project_category`.

### URL и шаблоны

| URL | Назначение | Шаблон |
|---|---|---|
| `/projects/` | Страница-раздел с карточками трёх подразделов и счётчиками записей | `archive-project.php` |
| `/projects/ustanovka-rsp/` | Проекты по установке рельсовых страховочных пакетов | `taxonomy-project_category.php` |
| `/projects/vyrubka-dkr/` | Проекты по вырубке древесно-кустарниковой растительности | `taxonomy-project_category.php` |
| `/projects/obshchestroitelnye-raboty/` | Проекты по общестроительным работам | `taxonomy-project_category.php` |
| `/project/<slug>/` | Детальная страница конкретного объекта | `single-project.php` |

Назначение категорий:

| Slug | Название |
|---|---|
| `ustanovka-rsp` | Установка рельсовых страховочных пакетов |
| `vyrubka-dkr` | Вырубка древесно-кустарниковой растительности |
| `obshchestroitelnye-raboty` | Общестроительные работы |

Три термина создаются при активации темы, если термин с соответствующим slug ещё не существует. Страница `/projects/` выводит категории с помощью `get_terms()` и показывает их текущие счётчики.

### Важное правило для URL

В `inc/cpt.php` архив типа записей `project` использует slug `projects`, а страницы отдельных записей — slug `project`. Таксономия `project_category` тоже использует префикс `projects`. Это намеренное решение:

- архив: `/projects/`;
- категории: `/projects/<category-slug>/`;
- отдельный проект: `/project/<project-slug>/`.

Фильтр `rewrite_rules_array` в `inc/cpt.php` даёт приоритет правилам архива `/projects/`. Не меняйте эти slugs или фильтр без проверки всей схемы URL: легко получить конфликт между архивом и таксономией и ответы 404.

После изменения `register_post_type()`, `register_taxonomy()` или правил rewrite откройте **Настройки → Постоянные ссылки** и нажмите **Сохранить изменения**.

### Метаполя проекта

| Поле в интерфейсе | Ключ в базе | Формат и назначение |
|---|---|---|
| Регион | `_project_region` | Обычная строка; выводится в карточке и на детальной странице |
| Заказчик | `_project_customer` | Обычная строка; выводится как заказчик проекта |
| Состав работ | `_project_works` | По одному пункту на строку; используется в карточке и подробном описании |
| Дополнительно | `_project_additional` | Необязательный список дополнительных работ, по одному пункту на строку |
| Галерея | `_project_gallery` | Список ID вложений через запятую; выбирается кнопкой медиабиблиотеки в редакторе |
| Основное содержимое записи | `post_content` | Описание объекта; выводится над перечнем работ на детальной странице |
| Порядок меню | `menu_order` | Числовой порядок проекта в списке; меньшее значение отображается раньше |
| Изображение записи | `thumbnail` / featured image | Основное изображение карточки проекта |

Списки работ и дополнительных работ должны содержать один пункт на строку. В поле **Состав работ** строка, начинающаяся с `## `, используется как жирный подзаголовок на детальной странице. В карточке проекта такие строки скрываются и не учитываются при подсчёте оставшихся пунктов.

Сортировка в категориях: сначала `menu_order` по возрастанию, затем дата записи по возрастанию. Не полагайтесь только на дату для ручного выстраивания списка — задавайте порядок проекта явно.

## Добавление и редактирование проекта

1. Откройте **Проекты → Добавить новый** в административной панели WordPress.
2. Укажите заголовок. Проверьте слаг записи, если URL должен быть задан определённым образом.
3. В редакторе заполните описание объекта в основном содержимом записи.
4. Выберите категорию проекта в блоке **Категории проектов**. Каждая запись должна находиться в правильном подразделе.
5. Установите **Изображение записи** — оно используется как обложка карточки.
6. В метаблоке **Детали проекта** заполните регион, заказчика и состав работ. В списке работ используйте отдельную строку для каждого пункта.
7. При необходимости заполните дополнительные работы.
8. Нажмите **Выбрать изображения** для формирования галереи. Несколько изображений можно выбрать в медиабиблиотеке; выбранные ID сохраняются в поле галереи.
9. Задайте порядок проекта в атрибутах записи, если требуется определённая последовательность в категории.
10. Сохраните запись и проверьте карточку категории и детальную страницу на компьютере и телефоне.

При переносе сайта на новую установку WordPress нужно переносить не только код темы, но и записи `project`, метаполя, термины таксономии и прикреплённые изображения из медиабиблиотеки. Если перенести только Git-репозиторий, проекты и изображения автоматически не появятся.

## Настройки темы

Основные контактные параметры задаются через `get_theme_mod()` и настраиваются через Customizer. Для изменения настроек по умолчанию редактируйте `inc/customizer.php`, а не добавляйте значения напрямую в HTML-шаблоны.

Ключи Customizer:

| Ключ | Назначение |
|---|---|
| `ingi_slogan` | Слоган в шапке |
| `ingi_phone` | Телефон |
| `ingi_email` | Адрес получателя заявки с формы |
| `ingi_addr_main` | Основной адрес |
| `ingi_addr_extra` | Дополнительный адрес |
| `ingi_telegram` | URL Telegram |
| `ingi_whatsapp` | URL WhatsApp |
| `ingi_copyright` | Текст копирайта |
| `ingi_map_lat` | Широта центра карты |
| `ingi_map_lon` | Долгота центра карты |

При разработке всегда указывайте резервное значение вторым аргументом `get_theme_mod( 'key', 'default' )`, особенно для новых настроек.

## CSS, JavaScript и внешние зависимости

### CSS

- `assets/css/main.css` — основные компоненты и стили сайта.
- `assets/css/responsive.css` — адаптивные правила для меньших экранов.
- `assets/css/hotfix.css` — поздние корректировки, перекрывающие часть более ранних правил.
- `style.css` в корне темы — обязательный файл WordPress, также подключается через `get_stylesheet_uri()`.

Если стиль не применяется, проверьте селектор и специфичность, вкладку **Computed** в инструментах разработчика, порядок фактической загрузки файлов и наличие переопределений в `hotfix.css` и корневом `style.css`. Не добавляйте очередное переопределение до выяснения, какое правило реально побеждает.

В качестве основных параметров дизайна используются тёмные цвета и оранжевый акцент. Ключевые значения из текущего дизайна:

```css
--orange: rgb(239, 126, 25);
--accent-soft: rgb(251, 175, 90);
--dark: rgb(18, 18, 18);
--dark-2: rgb(30, 30, 30);
--grey-333: #333;
--container: 1140px;
```

Перед добавлением новой секции проверьте, нет ли похожего компонента в существующих шаблонах и стилях. Адаптивность должна быть реализована для новой разметки сразу, а не только после проверки десктопа.

### JavaScript и сторонние библиотеки

`assets/js/main.js` содержит логику мобильного меню, плавного перехода к форме, AJAX-отправки формы, ленивой загрузки карты и анимаций.

В текущем `inc/enqueue.php` подключаются:

- шрифт Inter через Google Fonts;
- AOS 2.3.1 через `unpkg.com`;
- GSAP 3.12.2 и ScrollTrigger через CDNJS;
- основной `assets/js/main.js` с зависимостями от jQuery и библиотек анимации.

Скрипт Яндекс Карт подгружается из `main.js` при приближении контейнера карты к области видимости. Координаты берутся из атрибутов `data-lat` и `data-lon`, которые формирует `template-parts/map.php`.

Внешние ресурсы требуют доступности соответствующих доменов у посетителя сайта. Если сайт должен работать в закрытой сети или без внешних CDN, схему подключения библиотек придётся изменить отдельно.

### Кеширование

CSS и JavaScript темы получают версию по времени изменения файла через `filemtime()` в `inc/enqueue.php`. После изменения ресурсов:

1. проверьте, что редактируется нужный файл;
2. выполните жёсткое обновление браузера (`Ctrl+Shift+R`);
3. при наличии кеширующего плагина, CDN или серверного кеша очистите его;
4. в инструментах разработчика убедитесь, что браузер загрузил актуальный файл.

## Форма обратной связи

Фронтенд формы находится в `template-parts/cta-form.php`, обработчик — в `inc/ajax-form.php`, клиентский код — в `assets/js/main.js`.

Обработчик использует AJAX-действие `ingi_send`, nonce `ingi_form` и отправку через `wp_mail()`. В письме передаются поля ИНН, имени и телефона. Получатель задаётся настройкой `ingi_email`; телефон и отметка согласия проверяются на сервере.

**Важно:** наличие обработчика не гарантирует доставку писем. Результат `wp_mail()` зависит от почтовой конфигурации сервера. До запуска на рабочем домене выполните реальный тест отправки и получения письма, проверьте адрес получателя, SMTP/почтовую конфигурацию и текст согласия с обработкой персональных данных. Защиту от спама и частых повторных отправок следует оценить отдельно. Полная проверка цепочки «форма → письмо → ответ посетителю» в проектном хендовере пока не отмечена как завершённая.

## Разработка и правила внесения изменений

1. **Отделяйте логику от шаблонов.** Регистрацию типов записей, настройки и обработчики размещайте в подходящем файле `inc/`. Не превращайте файлы страниц в большие скрипты PHP-логики.
2. **Переиспользуйте компоненты.** Повторяющуюся разметку выносите в `template-parts/` и подключайте через `get_template_part()`.
3. **Подключайте ресурсы централизованно.** Новые CSS и JS регистрируйте в `inc/enqueue.php`, не вставляйте отдельные `<script>` и `<link>` в шаблоны без необходимости.
4. **Экранируйте вывод.** Используйте подходящие функции WordPress: `esc_html()`, `esc_attr()`, `esc_url()`, `wp_kses_post()` и другие по контексту.
5. **Используйте резервные значения Customizer.** Все обращения `get_theme_mod()` должны иметь разумный default.
6. **Сохраняйте архитектуру маршрутов проектов.** Перед изменением CPT, таксономии или rewrite rules проверяйте, не ломаются ли архив, категории и отдельные записи.
7. **Не считайте контент частью Git.** Изменение кода темы не заменяет резервное копирование базы данных и каталога загрузок.
8. **Сравнивайте оригинал и тестовый сайт.** Для визуальных доработок проверяйте одинаковую секцию на обоих сайтах, включая мобильную ширину.
9. **Не полагайтесь на AOS для мобильной видимости.** В текущей адаптивной вёрстке анимации появления на мобильных отключаются стилями, чтобы содержимое не оставалось скрытым.
10. **Не удаляйте вспомогательные CSS-переопределения вслепую.** Сначала проверьте каскад и фактический порядок загрузки.

Для локализации используется текстовый домен `ingigroup`, зарегистрированный в `inc/setup.php`. Существующие строки шаблонов не все оформлены как переводимые, поэтому при расширении мультиязычности потребуется отдельный проход по строкам интерфейса.
