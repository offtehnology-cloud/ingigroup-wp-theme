# IngiGroup — WordPress Theme

Кастомная классическая тема WordPress для сайта компании **«ИНЖИГРУПП»**. Тема реализует дизайн сайта, шаблоны страниц, отдельные типы записей, контактные настройки, галереи, формы обратной связи и адаптивную навигацию.

- **GitHub:** <https://github.com/offtehnology-cloud/ingigroup-wp-theme>
- **Основной сайт:** <https://ingigroup.ru/>
- **Текущая основная ветка:** `main`
- **Имя темы в WordPress:** `IngiGroup`
- **Каталог темы:** `wp-content/themes/ingigroup/`

> **Важно:** репозиторий содержит код темы, но не является полной резервной копией WordPress-сайта. Записи, страницы, метаданные, меню, настройки Customizer, учётные записи, плагины и медиафайлы из `wp-content/uploads/` хранятся в базе данных и/или файловой системе конкретного сайта. Для переноса сайта одной установки темы недостаточно.

## Назначение и архитектура

IngiGroup — классическая PHP-тема WordPress. Разметка страниц формируется PHP-шаблонами, повторяющиеся секции вынесены в `template-parts/`, функции темы и интеграции с WordPress находятся в `inc/`, стили и JavaScript — в `assets/`.

Это не блочная FSE-тема: в репозитории нет обязательного этапа сборки через Node.js, npm, Composer или Vite. Для обычного изменения PHP, CSS и JavaScript достаточно редактора кода и рабочего WordPress-окружения.

### Что реализовано в теме

- главная страница с первым экраном, услугами, преимуществами, блоками сертификатов и отзывов, формой заявки и картой;
- страницы «О компании» и «Контакты»;
- отдельные страницы основных услуг;
- раздел проектов, категории и детальные страницы объектов;
- архив сертификатов;
- архив отзывов и просмотр сканов отзывов;
- страницы производства и валки с галереями;
- политика конфиденциальности;
- общая модальная форма обратного звонка;
- адаптивная шапка, мобильное меню и подвал;
- настройки контактов, офисов, реквизитов и координат карты через Customizer;
- AJAX-обработчик формы WordPress;
- анимации, галереи и лайтбокс.

### Важный принцип разделения данных

В проекте используются два подхода:

1. **Содержимое, заданное в PHP-шаблонах.** Некоторые блоки главной и текстовые секции посадочных страниц являются статическими. Их изменение требует редактирования соответствующего PHP-файла.
2. **Содержимое из WordPress.** Проекты, сертификаты и отзывы используют Custom Post Types (CPT), записи, рубрики, миниатюры и метаполя. Эти данные находятся в базе данных WordPress, а не в Git.

Не следует считать, что установка темы на чистый WordPress автоматически создаст весь контент сайта или наполнит его проектами и изображениями.

## Состав сайта и URL

Ниже приведены основные маршруты, на которые рассчитаны текущие шаблоны. Фактический URL зависит также от slug страницы/записи и настроек постоянных ссылок в WordPress.

| Раздел | Ожидаемый адрес | Реализация |
|---|---|---|
| Главная | `/` | `front-page.php` и `template-parts/` |
| О компании | `/company/` | `page-company.php` |
| Контакты | `/contacts/` | `page-contacts.php` |
| Установка РСП | `/service/` | `page-service.php` |
| Производство | `/production/` | `page-production.php` |
| Аренда | `/rent/` | `page-rent.php` |
| Монтаж | `/installation/` | `page-installation.php` |
| Проектирование/разработка | `/development/` | `page-development.php` |
| Валка деревьев | `/felling/` | `page-felling.php` |
| Проекты | `/projects/` | архив CPT `project`, `archive-project.php` |
| Категория проектов | `/projects/<slug>/` | `taxonomy-project_category.php` |
| Отдельный проект | `/project/<slug>/` | `single-project.php` |
| Сертификаты | `/certificates/` | `archive-certificate.php` |
| Отзывы | `/opinions/` | `archive-opinion.php` |
| Политика конфиденциальности | `/privacy/` | `page-privacy.php` |
| Отдельный отзыв | `/opinions/<slug>/` | `single-opinion.php`, перенаправление в архив |

### Не путайте страницу `/service/` и тип записей `service`

`/service/` — обычная страница WordPress, использующая `page-service.php` и содержащая посадочную страницу установки РСП.

В `inc/cpt.php` дополнительно зарегистрирован CPT `service` с базовым rewrite-slug `services`. Для одиночной записи этого типа используется `single-service.php`. Это отдельный механизм; карточки услуг на главной не заполняются автоматически из CPT `service`.

Для CPT `service` в текущем корне темы нет отдельного `archive-service.php`. Перед использованием архива `/services/` проверьте фактический шаблон, который WordPress выберет по иерархии шаблонов.

## Требования и внешние зависимости

### Требования темы

В заголовке `style.css` указаны следующие значения:

- Requires at least: WordPress 6.0;
- Tested up to: WordPress 6.6;
- Requires PHP: 7.4;
- версия темы: `1.0.0`.

Эти значения — метаданные темы, а не подтверждение тестирования на любой более поздней версии. Перед публикацией проверьте тему на версиях WordPress и PHP, установленных на целевом хостинге. Для рабочего сайта используйте поддерживаемую хостингом версию PHP и актуальные обновления WordPress.

### Внешние библиотеки и сервисы

Текущая реализация обращается к внешним ресурсам:

| Ресурс | Назначение |
|---|---|
| Google Fonts — Inter | Шрифт интерфейса |
| AOS 2.3.1 | Анимации появления элементов |
| GSAP 3.12.2 | Анимации |
| GSAP ScrollTrigger | Привязка анимаций к прокрутке |
| jQuery из WordPress | JavaScript-зависимость темы |

Для загрузки внешних библиотек и карт серверу и браузеру посетителя требуется доступ к соответствующим доменам. При ограничении внешних подключений библиотеки нужно размещать локально и корректировать `inc/enqueue.php`.

В репозитории не предусмотрен обязательный запуск npm/composer-команд. Не запускайте случайные команды сборки — отдельная сборочная конфигурация в проекте не заявлена.

## Установка темы

### Вариант A. Установка из ZIP

1. Откройте [репозиторий темы](https://github.com/offtehnology-cloud/ingigroup-wp-theme).
2. Выберите **Code → Download ZIP**.
3. Распакуйте архив на компьютере.
4. Скопируйте каталог темы в `wp-content/themes/`.
5. Проверьте, что основные файлы находятся непосредственно в каталоге `ingigroup/`:

   ```text
   wp-content/themes/ingigroup/style.css
   wp-content/themes/ingigroup/functions.php
   wp-content/themes/ingigroup/front-page.php
   ```

   Не должно получиться лишнего уровня вложенности вида `ingigroup/ingigroup-wp-theme-main/style.css`.

6. Войдите в WordPress → **Внешний вид → Темы**.
7. Активируйте тему **IngiGroup**.
8. Перейдите в **Настройки → Постоянные ссылки** и нажмите **Сохранить изменения**.
9. Проверьте главную, страницы услуг, проекты, сертификаты и отзывы.

### Вариант B. Установка через Git

Если на сервере есть SSH и Git:

```bash
cd /path/to/wordpress/wp-content/themes/
git clone https://github.com/offtehnology-cloud/ingigroup-wp-theme.git ingigroup
```

Если каталог `ingigroup` уже существует, не клонируйте поверх него без резервной копии и проверки локальных изменений.

Для обновления существующей Git-копии:

```bash
cd /path/to/wordpress/wp-content/themes/ingigroup
git status
git pull --ff-only origin main
```

Команда `git pull` может перезаписать/не применить локальные изменения в зависимости от состояния репозитория. Сначала проверьте `git status`, сохраните собственные правки и только затем обновляйте файлы.

### После установки

- Назначьте логотип в настройках сайта, если он не задан.
- Проверьте наличие страниц с ожидаемыми slug.
- Назначьте меню в четырёх предусмотренных местах темы.
- Заполните настройки контактов и офиса.
- Проверьте записи CPT и загрузки изображений.
- Проверьте отправку письма с формы.

Активация темы не импортирует базу данных другого сайта.

## Первичная настройка WordPress

### Общие настройки

В **Настройки → Общие** проверьте:

- название сайта;
- адрес WordPress (URL);
- адрес сайта (URL);
- язык и часовой пояс;
- адрес администратора.

На тестовом окружении адрес может быть `ingigroup.xyz`; на боевом сайте целевой адрес — `https://ingigroup.ru`. При полном переносе адреса меняются вместе с базой данных и файлами, а не только через настройки темы.

### Постоянные ссылки

Для сайта используется структура URL с понятными slug. После активации темы или изменения регистрации CPT откройте **Настройки → Постоянные ссылки** и сохраните конфигурацию. Это обновляет rewrite rules WordPress.

Не меняйте структуру постоянных ссылок действующего сайта без проверки старых URL и подготовки перенаправлений.

### Страницы

Если страницы не были перенесены из тестовой базы, создайте их в WordPress и задайте slug из таблицы выше. Для страниц с отдельными PHP-шаблонами используйте соответствующую структуру и проверьте, что WordPress определяет нужный шаблон.

Шаблоны `page-company.php`, `page-contacts.php`, `page-production.php`, `page-felling.php`, `page-rent.php`, `page-installation.php`, `page-development.php`, `page-service.php` и `page-privacy.php` привязаны к slug или назначению страницы. Для правильной работы slug страницы должен соответствовать ожидаемому.

### Настройка меню

Тема регистрирует следующие места меню:

| Место в теме | Назначение |
|---|---|
| `primary` | Основное меню шапки |
| `services_menu` | Горизонтальное меню услуг |
| `footer_services` | Ссылки на услуги в подвале |
| `footer_docs` | Документы/ссылки в подвале |

Назначьте меню через **Внешний вид → Меню** либо соответствующий интерфейс редактора навигации, доступный в вашей версии WordPress. Проверьте мобильное меню отдельно: в мобильной навигации используется основное меню и меню услуг.

## Главная страница

Главная выводится через `front-page.php`. Основные секции подключаются отдельными файлами из `template-parts/`.

| Секция | Файл | Особенности |
|---|---|---|
| Первый экран | `template-parts/hero.php` | Заголовок, фоновое изображение, CTA |
| Услуги | `template-parts/services.php` | Карточки и ссылки заданы в PHP |
| Преимущества | `template-parts/advantages.php` | Статические элементы и SVG |
| Сертификаты | `template-parts/certificates.php` | Статические изображения из темы |
| Отзывы | `template-parts/opinions.php` | Статические изображения из темы |
| Форма заявки | `template-parts/cta-form.php` | AJAX-форма |
| Карта | `template-parts/map.php` | Интерактивная Яндекс Карта |

### Изменение карточек услуг

Карточки главной страницы не следует считать автоматическим списком всех записей CPT `service`. Их состав и адреса задаются в `template-parts/services.php`. При добавлении или переименовании услуги обновите соответствующий массив/разметку, проверьте ссылки и мобильную сетку.

### Изображения главной страницы

Часть изображений хранится непосредственно в `assets/images/`. Это не записи медиатеки WordPress. При переносе темы необходимо переносить весь каталог `assets/`, а не только PHP-файлы.

## Страницы услуг

Основные посадочные страницы — обычные страницы WordPress с отдельными PHP-шаблонами. Они не являются автоматически генерируемым архивом CPT `service`.

| Страница | Файл темы | Что проверять |
|---|---|---|
| Установка РСП | `page-service.php` | Текст услуги, блоки/спойлеры, CTA |
| Производство | `page-production.php` | Описание производства, характеристики, галерея |
| Аренда | `page-rent.php` | Тарифные/ценовые таблицы, CTA |
| Монтаж | `page-installation.php` | Описание работ, иллюстрации |
| Разработка | `page-development.php` | Текстовые секции и изображения |
| Валка деревьев | `page-felling.php` | Текст, нормативные/информационные секции, галерея |

Содержимое этих шаблонов частично задано непосредственно в PHP. Редактирование текста страницы в обычном визуальном редакторе WordPress не обязательно изменит все секции, если шаблон выводит статическую разметку.

### CPT `service`

`inc/cpt.php` также регистрирует тип записей `service`. У него есть поддержка заголовка, редактора, миниатюры, отрывка и порядка страниц, а для одиночной записи используется `single-service.php`.

Это не заменяет шесть описанных выше посадочных страниц. Не создавайте дубли страниц и CPT с одинаковыми slug без понимания правил маршрутизации WordPress.

## Проекты и категории проектов

Раздел проектов реализован через Custom Post Type `project` и таксономию `project_category`.

- архив проектов: `/projects/`;
- отдельный объект: `/project/<slug>/`;
- категория: `/projects/<category-slug>/`.

Основные файлы:

- `inc/cpt.php` — регистрация CPT и таксономии;
- `archive-project.php` — общий архив/страница раздела проектов;
- `taxonomy-project_category.php` — список проектов выбранной категории;
- `single-project.php` — детальная страница объекта;
- `template-parts/project-card.php` — карточка проекта;
- `inc/meta-boxes.php` — метабоксы проекта (см. техническое замечание ниже).

### Категории

При переключении темы код создаёт три стандартных термина таксономии, если их ещё нет:

| Slug | Назначение |
|---|---|
| `ustanovka-rsp` | Установка РСП |
| `vyrubka-dkr` | Валка/удаление деревьев и кустарника |
| `obshchestroitelnye-raboty` | Общестроительные работы |

Не удаляйте категории и не меняйте их slug на рабочем сайте без проверки URL и перенаправлений.

### Данные проекта

Детальная страница `single-project.php` использует метаполя:

| Meta key | Значение |
|---|---|
| `_project_region` | Регион/место проведения работ |
| `_project_customer` | Заказчик |
| `_project_works` | Состав выполненных работ |
| `_project_additional` | Дополнительная информация |
| `_project_gallery` | Галерея изображений (ID вложений) |

Миниатюра проекта задаётся как Featured Image. Порядок списка учитывает `menu_order`, затем дату публикации; для ручной сортировки используйте поле порядка, если оно доступно в редакторе.

Важное ограничение: текущий `functions.php` не подключает `inc/meta-boxes.php`, хотя сам файл присутствует в репозитории, а шаблоны читают перечисленные метаполя. Поэтому наличие файла метабоксов ещё не означает, что соответствующие поля доступны в админке. До исправления подключения проверьте, каким способом метаданные уже внесены в базу и доступны ли поля редактору.

### Правило вывода поля работ

В `single-project.php` есть специальная обработка строк состава работ, начинающихся с `Объект:`. Не меняйте формат существующего текста без проверки результата на опубликованной детальной странице.

## Сертификаты

На главной странице блок сертификатов использует отдельные статические изображения. Поэтому изменение записей CPT не обязательно меняет изображения в блоке главной.

## Отзывы

`single-opinion.php` перенаправляет посетителя на архив отзывов. Отдельная детальная страница отзыва не является основным пользовательским сценарием.

Архив также выводит сканы отзывов из статических файлов темы `assets/images/opinion-1.jpg` … `assets/images/opinion-9.jpg`. На главной карточки отзывов также используют статические изображения. Следовательно, CPT-отзывы и изображения сканов — связанные, но отдельные источники контента.

## Галереи производства и валки

Галерея производства и валки использует метаполе `_ingi_gallery`, которое заполняется через медиабиблиотеку WordPress. Код метабокса находится в `inc/meta-boxes-production-gallery.php` и подключается через `functions.php`.

Метабокс предназначен для страниц со slug `production` и `felling`. Изображения выбираются из медиатеки, а в метаполе сохраняется список ID вложений в виде строки, разделённой запятыми.

Для производства `page-production.php` разбирает строку ID и выводит выбранные изображения. При отсутствии выбранной галереи используется статический fallback из `assets/images/production/`.

**Известное ограничение страницы валки:** `page-felling.php` проверяет значение `_ingi_gallery` как массив, тогда как метабокс сохраняет строку с ID через запятую. Поэтому выбранная в админке галерея может не отображаться; шаблон использует статические файлы `felling-gallery-1.jpg` … `felling-gallery-8.jpg`. Перед использованием этого интерфейса требуется согласовать формат чтения и записи метаданных.

При удалении или замене изображений проверьте и медиатеку WordPress, и каталог темы: статические fallback-файлы не заменяются автоматически файлами из медиатеки.

## Формы обратной связи

Обработчик находится в `inc/ajax-form.php`. Отправка выполняется через WordPress AJAX (`wp-admin/admin-ajax.php`) с помощью `wp_mail()`.

### Поля формы

Основная форма содержит:

- ИНН;
- имя;
- телефон;
- согласие с обработкой персональных данных;
- скрытые технические поля, необходимые для обработки запроса.

Модальное окно обратного звонка использует отдельный набор полей; в частности, поле ИНН там может быть пустым. JavaScript находится в `assets/js/main.js`.

### Серверная обработка

Обработчик:

1. Проверяет WordPress nonce формы.
2. Очищает значения полей.
3. Проверяет наличие обязательных данных и согласия.
4. Берёт адрес получателя из `ingi_email` (резервное значение — `info@ingigroup.ru`).
5. Отправляет письмо через `wp_mail()`.
6. Возвращает JSON-результат AJAX-запроса.

### Настройка и проверка почты

1. Установите реальный адрес получателя в **Внешний вид → Настроить → ИНЖИГРУПП — Контакты**.
2. Убедитесь, что на хостинге настроена отправка почты PHP/WordPress. Для надёжной доставки обычно требуется настроенный SMTP-транспорт или почтовый плагин.
3. Отправьте тестовую заявку с публичной страницы.
4. Проверьте получение письма, тему, кодировку и содержимое всех полей.
5. Проверьте отправку из модального окна и основной формы отдельно.
6. Проверьте поведение при пустом телефоне, отсутствии согласия и ошибке почтовой отправки.

Сам факт успешного AJAX-ответа не гарантирует доставку письма в папку «Входящие»: проверьте фактическую доставку и спам.

## Карты, аналитика и внешние сервисы

### Карты

- Главная и повторно используемый блок карты используют JavaScript-карту Яндекса. Скрипт карты загружается отложенно при появлении блока в зоне видимости, если доступен `IntersectionObserver`.
- Страница контактов выводит два офиса и две карты через iframe Яндекса.
- Основные координаты берутся из настроек Customizer; для второго офиса предусмотрены отдельные координаты.

После переноса проверьте обе карты, адреса, маркеры, адаптивность и доступность доменов Яндекса.

### Яндекс.Метрика

В `footer.php` код Яндекс.Метрики и идентификатор счётчика `114134226` указаны непосредственно в коде темы. Перед публикацией убедитесь, что это правильный счётчик именно для боевого сайта. При необходимости перенесите идентификатор в настройки, а также проверьте требования к уведомлению о cookies/аналитике и политике конфиденциальности.

### Внешние библиотеки

Стили и скрипты AOS, GSAP и ScrollTrigger подключаются из CDN. Если CDN блокируется или недоступен, анимации могут не работать, хотя основная HTML-разметка должна оставаться доступной. Для полностью автономного размещения потребуется локализовать библиотеки и изменить `inc/enqueue.php`.

## Разработка и внесение изменений

### Рабочий процесс

1. Работайте в отдельной копии темы или на staging-сайте.
2. Перед правками сохраните текущую версию файлов и базу данных тестового сайта.
3. Вносите изменения в соответствующий PHP-модуль, шаблон, CSS или JS.
4. Проверяйте PHP на синтаксические ошибки.
5. Проверяйте связанные страницы и разрешения.
6. Проверяйте логи PHP/WordPress и консоль браузера.
7. Коммитьте связанные изменения одним логическим набором.
8. После публикации обновляйте документацию, если изменились URL, CPT, метаполя, настройки или зависимости.

Сначала определите, откуда выводится нужный блок:

- отдельный `page-*.php`;
- запись CPT и её метаданные;
- настройка Customizer;
- изображение в `assets/`;
- запись/файл в медиатеке WordPress.

Не начинайте с редактирования страницы в визуальном редакторе, пока не установлено, что шаблон выводит `the_content()`: отдельные шаблоны содержат статические секции.

### Добавление новой страницы

1. Создайте страницу WordPress и задайте уникальный slug.
2. Определите, подходит ли общий `page.php` или необходим отдельный шаблон.
3. Если нужен отдельный шаблон, создайте `page-{slug}.php` и используйте стандартные `get_header()`, `get_footer()`, цикл WordPress и безопасный вывод данных.
4. Добавьте ссылку в нужные меню.
5. Проверьте canonical/SEO, адаптивность, формы и внутренние ссылки.
6. При смене slug старой страницы подготовьте 301-перенаправление.

1. Создайте запись типа «Проекты» (`project`).
2. Укажите заголовок и slug.
3. Назначьте одну из категорий `project_category`.
4. Добавьте миниатюру.
5. Заполните метаданные, которые используются `single-project.php`.
6. Настройте порядок отображения при необходимости.

Перед тем как считать интерфейс добавления проектов готовым, проверьте наличие метабоксов в админке: `inc/meta-boxes.php` присутствует, но текущий `functions.php` его не подключает.

Создайте запись `certificate`, задайте заголовок, миниатюру и порядок сортировки. Проверьте её появление на `/certificates/`. На главной блок сертификатов использует статические файлы и может не обновиться после добавления CPT-записи.

## Известные ограничения и технические замечания

Этот список фиксирует особенности, выявленные при просмотре текущей публичной версии репозитория. Перед изменением соответствующих файлов перепроверьте их состояние в рабочей копии.

### 1. Метабоксы проектов не подключены

`inc/meta-boxes.php` содержит интерфейс редактирования метаданных проекта, а `single-project.php` ожидает эти метаполя. Но `functions.php` в текущем виде не подключает `inc/meta-boxes.php`. Поэтому не следует обещать, что поля региона, заказчика, состава работ и галереи доступны в админке. Для восстановления интерфейса требуется явно подключить модуль и протестировать сохранение/вывод данных.

### 2. Галерея страницы валки

Метабокс галереи сохраняет `_ingi_gallery` в строковом формате — список ID через запятую. `page-production.php` разбирает строку, а `page-felling.php` проверяет значение как массив. Это несоответствие может приводить к тому, что выбранные изображения на странице валки игнорируются, а шаблон использует fallback-файлы. Требуется унифицировать чтение и запись формата метаданных.

### 3. Статические секции и CPT — разные источники

Главная страница использует статические карточки услуг и локальные изображения сертификатов/отзывов. Создание новой записи CPT само по себе не гарантирует обновление главной страницы.

### 4. Тип записей `service`

CPT `service` зарегистрирован, но основные посадочные страницы услуг — отдельные страницы WordPress с собственными PHP-шаблонами. Не путайте `/service/` и архив `/services/`. Отдельный `archive-service.php` в корне темы отсутствует.

### 5. SEO

В теме есть интеграционный фильтр для Rank Math, отключающий кэширование sitemap. Это не означает, что SEO-плагин установлен или что для всех страниц заданы SEO title, description, Open Graph и schema. Проверьте SEO отдельно на целевом сайте.

### 6. Аналитика

ID Яндекс.Метрики прописан непосредственно в `footer.php`. При использовании темы на другом домене перепроверьте, что счётчик относится к нужному ресурсу, и оцените необходимость вынести ID в настройки.

### 7. Контент политики конфиденциальности

В шаблоне политики есть адрес `https://ingigroup.ru/`, заданный в тексте напрямую. При использовании другого домена или изменении юридических данных обновите текст и проверьте его с ответственным за обработку персональных данных.

### 8. Версии WordPress и PHP

Значение `Tested up to` в заголовке темы — 6.6, поэтому оно может отставать от установленного на хостинге WordPress. Проверяйте совместимость на тестовом окружении, а затем при необходимости обновите метаданные темы.

### 9. Изображение директора

Шаблон `template-parts/company/director.php` обращается к файлу `assets/img/director.jpg`. Проверьте наличие файла с точным регистром имени и расширением в архиве релиза. На Linux файловая система чувствительна к регистру.

## Перенос с `ingigroup.xyz` на `ingigroup.ru`

Если тестовая версия сайта находится на `ingigroup.xyz`, а боевой сайт должен работать на `ingigroup.ru`, переносите всю WordPress-установку — базу данных и файлы, а не только каталог темы.

### Что входит в перенос

- база данных WordPress;
- `wp-content/uploads/`;
- каталог темы `wp-content/themes/ingigroup/`;
- установленные плагины и их файлы;
- `wp-config.php` и серверные настройки (учётные данные на новом сервере должны быть своими);
- пользовательские настройки, меню, записи CPT, страницы и метаданные из базы данных.

### Рекомендуемый порядок

1. Создайте резервные копии тестового сайта: SQL-дамп базы и архив файлов.
2. Подготовьте новый хостинг и чистую базу данных.
3. Перенесите файлы и импортируйте базу.
4. Настройте `wp-config.php` под новую БД.
5. Выполните безопасную замену старого домена на новый с помощью WP-CLI:

   ```bash
   wp search-replace 'https://ingigroup.xyz' 'https://ingigroup.ru' --all-tables --precise --skip-columns=guid --dry-run
   ```

   Проверьте результат `--dry-run`. Если он корректен, выполните команду без `--dry-run`:

   ```bash
   wp search-replace 'https://ingigroup.xyz' 'https://ingigroup.ru' --all-tables --precise --skip-columns=guid
   ```

   Если сайт использовал несколько вариантов адреса (`http://`, `www`, без `www`), отдельно проверьте наличие таких значений и заменяйте только действительно используемые варианты. Не используйте обычный SQL `REPLACE()` для сериализованных данных WordPress.

6. Установите корректные `home` и `siteurl`:

   ```bash
   wp option update home 'https://ingigroup.ru'
   wp option update siteurl 'https://ingigroup.ru'
   ```

7. Включите HTTPS/SSL на новом хостинге.
8. Сохраните **Настройки → Постоянные ссылки** или выполните `wp rewrite flush`.
9. Проверьте контакты, карты, формы, письма, изображения, меню и все типы записей.
10. Настройте DNS домена на новый хостинг и проверьте сайт снаружи.
11. Настройте 301-редиректы для URL, которые изменились.
12. Сохраните старый тестовый сайт и резервные копии до завершения проверки.

Перед переключением DNS убедитесь, что старый сайт-донор больше не должен обслуживать домен `ingigroup.ru` на прежнем хостинге. Один домен должен вести на выбранную публичную версию сайта.

### После запуска

- проверьте сертификат SSL и отсутствие смешанного контента;
- проверьте `home`/`siteurl`, canonical и sitemap;
- перепроверьте формы и фактическую доставку почты;
- проверьте обе карты и координаты офисов;
- очистите кеш WordPress, плагинов, сервера и CDN;
- проверьте журналы ошибок;
- создайте резервную копию уже работающего боевого сайта.

## Безопасность и резервное копирование

- Не храните пароли БД, SMTP, API-ключи и доступы к хостингу в Git.
- Не загружайте в публичный репозиторий дампы базы, пользовательские данные и приватные документы.
- Перед обновлением темы сохраняйте резервную копию базы и файлов.
- Используйте обновляемые версии WordPress, PHP и плагинов.
- Не отключайте nonce и серверную проверку формы ради упрощения тестирования.
- Проверяйте экранирование данных при выводе и санитаризацию входных данных при добавлении новых полей.
- Ограничивайте права пользователей WordPress по принципу минимально необходимых.
- Храните копии резервных данных отдельно от того же хостинга.
