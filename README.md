# IngiGroup WordPress Theme

Кастомная классическая тема WordPress для сайта инжиниринговой компании «ИНЖИГРУПП». Проект воспроизводит структуру, внешний вид и поведение исходного сайта [ingigroup.ru](https://ingigroup.ru/) и переносит управление содержимым на WordPress.

- **Репозиторий:** <https://github.com/offtehnology-cloud/ingigroup-wp-theme>
- **Тестовый сайт:** <https://ingigroup.xyz/>
- **Сайт-образец:** <https://ingigroup.ru/>
- **Подробный хендовер проекта:** [ingigroup-handover-v14.md](./ingigroup-handover-v14.md)

> **Важно:** Git-репозиторий содержит файлы темы, шаблоны, стили и скрипты. Записи WordPress, меню, настройки Customizer и содержимое медиатеки конкретного сайта находятся в базе данных и `wp-content/uploads` и автоматически из репозитория не восстанавливаются.

## Назначение и возможности

Тема использует классическую архитектуру WordPress: PHP-шаблоны, хуки WordPress, пользовательские типы записей, таксономию и стандартные настройки темы. Обязательной сборки через Node.js, Composer или другого этапа компиляции в текущем проекте нет.

Реализованные части сайта:

- главная страница с адаптивной шапкой, главным меню, услугами, преимуществами, сертификатами, отзывами, формой заявки и картой;
- раздел реализованных проектов с тремя категориями и отдельными страницами объектов;
- страницы «О компании» и «Контакты»;
- архивы сертификатов и отзывов;
- шесть отдельных посадочных страниц услуг;
- страница политики конфиденциальности;
- общая модалка «Оставить заявку»;
- адаптивная навигация, анимации, галереи и лайтбокс;
- настройки контактных данных, социальных ссылок и карты через WordPress Customizer;
- обработчик AJAX-формы через `wp-admin/admin-ajax.php`;
- шаблон страницы 404.

Цель — сохранять сходство с сайтом-образцом, но при этом оставлять контент управляемым через админ-панель, где это предусмотрено архитектурой страницы.

## Требования и зависимости

Необходимы:

- установленный и работающий WordPress;
- PHP и база данных, совместимые с установленной версией WordPress;
- доступ к `wp-content/themes/` для установки или обновления темы;
- исходящие подключения к используемым внешним CDN и сервису Яндекс Карт, если эти ресурсы должны загружаться с внешних серверов.

В репозитории не зафиксированы проверенные минимальные версии WordPress и PHP. Перед использованием на рабочем сайте проверьте тему в тестовой среде с теми же версиями WordPress и PHP, что и на целевом сервере.

### Внешние ресурсы

В текущей реализации используются:

- шрифт Inter через Google Fonts;
- AOS для анимаций появления элементов;
- GSAP и ScrollTrigger для анимационных эффектов;
- jQuery из поставки WordPress;
- API Яндекс Карт для картографического блока;
- AJAX WordPress через `admin-ajax.php`.

Сборщик фронтенда, `package.json`, `composer.json` и отдельный обязательный плагин для запуска темы не предусмотрены. Если сайт должен работать в сети без доступа к CDN, внешние библиотеки потребуется разместить локально и изменить подключение в `inc/enqueue.php`.

## Установка

### Вариант 1. Установка через Git

Перейдите в каталог тем вашего WordPress и клонируйте репозиторий:

```bash
cd /path/to/wordpress/wp-content/themes/
git clone https://github.com/offtehnology-cloud/ingigroup-wp-theme.git ingigroup
```

Проверьте, что структура получилась правильной и файлы темы расположены непосредственно в каталоге `ingigroup/`:

```text
wp-content/themes/ingigroup/style.css
wp-content/themes/ingigroup/functions.php
wp-content/themes/ingigroup/front-page.php
```

Не клонируйте репозиторий поверх существующего рабочего каталога без проверки собственных изменений.

### Вариант 2. Установка через ZIP

1. Откройте страницу [репозитория GitHub](https://github.com/offtehnology-cloud/ingigroup-wp-theme).
2. Нажмите **Code → Download ZIP**.
3. Распакуйте архив.
4. Скопируйте файлы темы в `wp-content/themes/ingigroup/`.
5. Убедитесь, что `style.css` и `functions.php` лежат непосредственно в `ingigroup/`, а не в лишней вложенной папке `ingigroup-wp-theme-main/`.

### Активация

1. Откройте админ-панель WordPress.
2. Перейдите в **Внешний вид → Темы**.
3. Активируйте тему **IngiGroup**.
4. Откройте **Настройки → Постоянные ссылки** и нажмите **Сохранить изменения**, даже если формат ссылок не менялся.
5. Проверьте главную страницу и основные URL из раздела [«Страницы и URL»](#страницы-и-url).

После активации `inc/cpt.php` регистрирует пользовательские типы записей и автоматически создаёт три стандартных термина таксономии проектов, если их ещё нет.

### Обновление существующей установки через Git

Сначала убедитесь, что локальные изменения сохранены, а рабочий сайт резервирован. Затем выполните в каталоге темы:

```bash
git status
git pull
```

Если `git status` показывает локальные изменения, сначала разберите их и решите, какие изменения нужно сохранить. Не используйте `git reset --hard` или другие команды с удалением изменений без осознанного решения.

После изменений CPT, таксономий или правил URL обновите постоянные ссылки через админ-панель WordPress.

## Первичная настройка WordPress

### Меню

В теме используются следующие области меню:

| Идентификатор области | Назначение |
|---|---|
| `primary` | Основное меню в шапке и мобильная навигация |
| `services_menu` | Оранжевая полоса услуг; также используется в мобильном меню |
| `footer_services` | Ссылки на услуги в подвале |
| `footer_docs` | Ссылки на документы в подвале |

Создайте меню и назначьте его нужной области в **Внешний вид → Меню** (или в эквивалентном интерфейсе управления меню вашей версии WordPress).

Шесть главных услуг — это **обычные страницы WordPress с индивидуальными шаблонами**, а не записи CPT `service`. Поэтому ссылки меню на них должны указывать непосредственно на `/service`, `/production`, `/rent`, `/installation`, `/development` и `/felling`. В случае старых или сломанных пунктов проще пересоздать их как **Произвольные ссылки** с нужными URL.

Для выпадающих пунктов проверьте вложенность меню и параметр `depth` в соответствующем вызове `wp_nav_menu()`.

### Страницы и их слаги

При создании страницы услуги:

- используйте соответствующий слаг в нижнем регистре латиницей;
- выберите нужный шаблон страницы, указанный в таблице ниже;
- убедитесь, что страница опубликована и не создана в виде дубликата;
- проверьте назначение пунктов меню после изменения заголовка или слага.

Некоторые шаблоны используют `get_the_title()` в хлебных крошках, поэтому название страницы в админ-панели влияет на отображаемый текст хлебных крошек.

### Контент и медиатека

Загрузите необходимые изображения через **Медиафайлы → Добавить новый медиафайл**, если конкретный блок рассчитан на медиатеку. Отдельные секции пока используют статические файлы из `assets/images/`; см. разделы о сертификатах, отзывах и галереях.

Тема не переносит сама по себе контент с тестового сайта. При развёртывании на новой базе нужно переносить записи, таксономии, меню, настройки Customizer и связанные медиафайлы отдельно.

### Важно о структуре услуг

Шесть основных страниц услуг — обычные записи типа `page`, которым назначаются кастомные шаблоны `page-*.php`. CPT `service` по-прежнему регистрируется в `inc/cpt.php`, но оставлен как возможная основа для второстепенных услуг в будущем и сейчас не используется для шести главных посадочных страниц.

Не меняйте слаги `project` и `projects` без проверки всех rewrite-правил. Архив проектов должен открываться по `/projects/`, термины таксономии — по `/projects/<category>/`, а детальные страницы — по `/project/<slug>/`. После изменения маршрутов обновите постоянные ссылки в админке.

## Раздел «Проекты»

Раздел реализован на пользовательском типе записей `project` и таксономии `project_category`.

### Категории

| Слаг | Название |
|---|---|
| `ustanovka-rsp` | Установка рельсовых страховочных пакетов |
| `vyrubka-dkr` | Вырубка древесно-кустарниковой растительности |
| `obshchestroitelnye-raboty` | Общестроительные работы |

Если соответствующие термины отсутствуют, тема создаёт их при активации. Страница `/projects/` получает категории из WordPress и отображает текущие счётчики публикаций.

### Как добавить проект

1. В админке откройте **Проекты → Добавить новый**.
2. Заполните заголовок, слаг и основное содержимое записи. Основное содержимое используется как описание объекта.
3. Выберите одну из категорий проектов.
4. Установите **Изображение записи** — оно используется как изображение карточки.
5. Заполните метаблок **Детали проекта**.
6. При необходимости выберите несколько изображений для галереи.
7. Укажите порядок записи в атрибутах страницы/порядке меню, если список должен идти в определённой последовательности.
8. Опубликуйте запись и проверьте карточку в категории и детальную страницу.

### Метаполя проекта

| Поле | Ключ метаданных | Формат и назначение |
|---|---|---|
| Регион | `_project_region` | Строка, выводится в карточке и детальном описании |
| Заказчик | `_project_customer` | Строка с названием заказчика |
| Состав работ | `_project_works` | Многострочный список работ, один пункт на строку |
| Дополнительно | `_project_additional` | Необязательный список дополнительных работ, один пункт на строку |
| Галерея | `_project_gallery` | ID вложений WordPress, сохранённые через запятые; выбираются из медиатеки |
| Основное содержимое | `post_content` | Описание объекта, выводится перед списком работ |
| Порядок | `menu_order` | Числовой порядок отображения; меньшее число выводится раньше |
| Обложка | `thumbnail` | Основное изображение карточки |

В поле «Состав работ» строка, начинающаяся с `## `, отображается как жирный подзаголовок на детальной странице. В карточках проектов эти строки не выводятся как пункты списка.

Сортировка проектов по текущей логике: сначала `menu_order` по возрастанию, затем дата по возрастанию. Для управляемого порядка задавайте `menu_order` явно.

### Перенос проектов на другой WordPress

Записи `project`, значения их метаполей, термины `project_category`, избранные изображения и содержимое медиатеки хранятся вне репозитория. При переносе используйте экспорт/импорт WordPress или полноценную миграцию базы и файлов загрузок. Одного `git clone` для переноса контента недостаточно.

Скрипты первоначального импорта проектов удалены из рабочей темы после завершения импорта. Не рассчитывайте на автоматическое заполнение 30 объектов только после установки темы.

## Сертификаты и отзывы

### Сертификаты

Сертификаты реализованы как CPT `certificate`; архив выводится шаблоном `archive-certificate.php` по адресу `/certificates/`. Для записей сертификата предусмотрены заголовок, миниатюра и порядок отображения. Основной редактор записи не включён в `supports` CPT.

Архив содержит сетку изображений и лайтбокс. В текущей реализации предусмотрены статические файлы-фолбэки `assets/images/cert-1.jpg` … `assets/images/cert-10.jpg`. Наполнение CPT и перевод всех изображений на медиатеку можно продолжить отдельно.

### Отзывы

Отзывы реализованы как CPT `opinion`, архив выводится через `archive-opinion.php` по адресу `/opinions/`. Для отдельного отзыва шаблон `single-opinion.php` перенаправляет посетителя на архив отзывов.

Метабокс `inc/meta-boxes-opinion.php` позволяет указать автора и должность. В архиве есть карточки отзывов, сетка изображений и лайтбокс; предусмотрены статические файлы-фолбэки `assets/images/opinion-1.jpg` … `assets/images/opinion-9.jpg`.

### Лайтбокс

Универсальный лайтбокс реализован в `assets/js/main.js`. Текущие сетки, на которые рассчитана логика, включают:

- `.certificates-grid`;
- `.opinions-scans-grid`;
- `.production-gallery__grid`;
- `.felling-gallery__grid`.

При добавлении новой галереи проверьте её селектор в JavaScript и синхронность HTML-классов, CSS и логики переключения изображений.

| Ключ `get_theme_mod()` | Назначение |
|---|---|
| `ingi_slogan` | Слоган в шапке |
| `ingi_phone` | Телефон |
| `ingi_email` | Адрес получателя заявки с формы |
| `ingi_addr_main` | Основной адрес |
| `ingi_addr_extra` | Дополнительный адрес |
| `ingi_telegram` | Ссылка Telegram |
| `ingi_whatsapp` | Ссылка WhatsApp |
| `ingi_copyright` | Текст копирайта |
| `ingi_map_lat` | Широта карты |
| `ingi_map_lon` | Долгота карты |

У значений `get_theme_mod()` должен быть второй аргумент — резервное значение по умолчанию. При установке темы на новый сайт проверьте телефон, адреса, почту, социальные ссылки и координаты: пользовательские значения хранятся в базе данных, а не в PHP-файлах репозитория.

В `functions.php` также установлен фильтр `ingigroup_company_stats`, который задаёт значение первого показателя статистики страницы «О компании». Если меняется структура массива статистики в `template-parts/company/stats.php`, проверьте совместимость этого фильтра.

## Форма и модальное окно заявки

Тема использует общую форму обратной связи и модальное окно «Оставить заявку».

### Техническая схема

- Серверный обработчик: `inc/ajax-form.php`.
- Клиентская логика: `assets/js/main.js`.
- Отправка выполняется через `wp-admin/admin-ajax.php`, action — `ingi_send`.
- Адрес получателя читается из `ingi_email` в настройках темы.
- Общая CTA-форма вынесена в `template-parts/cta-form.php`.
- Модальное окно подключается из `footer.php` через `template-parts/modal-callback.php`.
- Кнопки открытия модалки используют класс `.js-open-callback`.
- Публичная функция для открытия окна из консоли браузера: `window.ingiOpenCallback()`.

### Важные CSS-классы и поля

Корневой класс модального окна — `.modal-callback`; старое имя `.ingi-modal*` не использовать. Логика JS опирается в том числе на `id="modal-callback"`, атрибут `data-modal-close`, класс формы `.js-ingi-form` и элемент статуса `.js-ingi-form-msg`.

Форма содержит поле телефона (`name="phone"`), чекбокс согласия (`name="agree"`), скрытое поле-ловушку (`name="inn"`) и `form_source`. В модальном окне текст согласия содержит ссылку на `/privacy/`, формируемую через `home_url()`.

При изменении разметки обязательно синхронно проверьте CSS и JS. В частности, не переименовывайте `name="agree"` или поле `inn`, не проверив соответствующие проверки в `main.js` и `inc/ajax-form.php`.

### Проверка формы

Реализация присутствует в коде, но завершённость серверной доставки письма нельзя считать подтверждённой только по наличию обработчика. На целевом хостинге нужно проверить полный цикл:

1. Открытие и закрытие модального окна, в том числе по Escape и клику по оверлею.
2. Обязательность телефона и согласия на обработку персональных данных.
3. Отображение сообщений об ошибке и успехе.
4. Запрос к `admin-ajax.php` в инструментах разработчика браузера.
5. Доставку письма адресату, заданному в настройках темы.
6. Работающий почтовый транспорт сервера WordPress (`wp_mail()`); при необходимости — настройку SMTP.

## Карта и внешние ресурсы

Общий блок карты находится в `template-parts/map.php`. Его подключают шаблоны, где требуется секция «Наш адрес». Используйте `get_template_part( 'template-parts/map' )` — без суффикса `.php`.

В `template-parts/map.php` есть проверка страницы по слагу. Если блок не выводится на новой странице, проверьте whitelist и добавьте слаг страницы, если это ожидаемое место карты. На `/contacts/` используется отдельный iframe-виджет карты; главная и страницы услуг используют текущую схему с Яндекс Картами.

Скрипт карты подгружается при приближении контейнера карты к области просмотра. Не удаляйте необходимые атрибуты контейнера (`data-lat`, `data-lon`) без синхронного изменения `main.js` и шаблона карты.

## CSS, JavaScript и дизайн-система

### Роль файлов CSS

- `assets/css/main.css` — основной стиль и компоненты страниц;
- `assets/css/responsive.css` — адаптация для планшетов и телефонов;
- `assets/css/hotfix.css` — поздние исправления, которые могут переопределять правила из `main.css`;
- корневой `style.css` — обязательный файл метаданных темы WordPress;
- `assets/css/style.css` — дополнительный файл стилей, используемый текущей темой.

Если стиль ведёт себя не так, как ожидается, откройте DevTools → **Computed**, проверьте порядок подключения и найдите правило, которое реально переопределяет значение. Сначала диагностируйте конфликт, затем меняйте селектор. Не добавляйте повторяющиеся правила в `hotfix.css` только потому, что изменение `main.css` визуально не сработало.

### Базовые цвета

В дизайн-системе используются следующие основные значения:

```css
--orange:        rgb(239, 126, 25);
```

При использовании CSS custom properties, которые могут отсутствовать в конкретном контексте, задавайте fallback, например `var(--grey-333, #333)`.

### JavaScript и версии ресурсов

Основная клиентская логика находится в `assets/js/main.js`: мобильное меню, переходы к форме, отправка AJAX, загрузка карты, AOS/GSAP-анимации, галереи и управление модальным окном. Подключение и версии ресурсов настраиваются в `inc/enqueue.php`. Для файлов темы используется `filemtime()`, чтобы после обновления стилей и скриптов браузер получал изменённую версию.

Если правка не появилась на сайте:

1. Выполните жёсткое обновление страницы (`Ctrl+Shift+R`).
2. Проверьте, что в `inc/enqueue.php` версия формируется по актуальному файлу.
3. Очистите кэш плагина, сервера или CDN, если они используются.
4. Убедитесь, что браузер не загрузил старый CSS/JS из кэша.

## Правила разработки

### Архитектура

- Разделяйте PHP-логику и HTML-разметку. Общие или повторяющиеся блоки выносите в `inc/` или `template-parts/`.
- Повторно используемые части выводите через `get_template_part()`.
- Подключайте стили и скрипты через `wp_enqueue_style()` и `wp_enqueue_script()` в `inc/enqueue.php`, а не жёсткими `<link>`/`<script>` в шаблонах без необходимости.
- Экранируйте значения при выводе с помощью подходящих функций WordPress: `esc_html()`, `esc_attr()`, `esc_url()` и т. д.
- Для ссылок на внутренние страницы используйте `home_url()`, а не жёстко закодированный домен тестового или основного сайта.
- При добавлении Customizer-параметров всегда указывайте значение по умолчанию в `get_theme_mod()`.

### Стилизация страниц услуг

Каждая основная услуга имеет индивидуальный шаблон и уникальные детали. Не пытайтесь встраивать весь контент услуг в один общий файл-шаблон. Общие элементы уже вынесены там, где это оправдано, например CTA-форма, хлебные крошки и карта.

Если заголовок hero на отдельной услуге длиннее стандартного, добавляйте scoped-модификатор, например `.development-hero` или `.felling-hero`, вместо изменения базового `.service-hero`, которое может сломать остальные страницы.

На мобильных экранах:

- не используйте `word-break: break-word` и `overflow-wrap: anywhere` для заголовков услуг — они могут разрывать слова по буквам;
- при необходимости скрывайте ручные `<br>` с помощью scoped-правил, сохраняя пробел перед `<br>` в HTML;
- проверяйте каскад стилей для размеров экрана до 991 px, 767 px и 480 px;
- учитывайте, что анимации AOS на мобильной версии принудительно отключаются правилами для `[data-aos]`.

### Галереи

Метабокс `inc/meta-boxes-production-gallery.php` поддерживает галерею для слагов `production` и `felling`; ключ метаданных — `_ingi_gallery`. Если медиатека не содержит выбранных изображений, некоторые шаблоны используют файловый фолбэк из `assets/images/`. Для новых страниц со своей галереей синхронно обновляйте allowlist слагов, PHP-рендер, файловый фолбэк при необходимости, CSS и селекторы лайтбокса в `main.js`.

Файловый фолбэк добавляйте только после проверки существования конкретного файла через `file_exists()`. Не предполагайте, что изображение доступно только потому, что оно есть в исходном HTML сайта-образца.

### Меню, URL и CPT

- После изменений в `register_post_type()`, `register_taxonomy()` или rewrite-правилах сохраняйте постоянные ссылки в админке.
- Не меняйте без необходимости схему `project`/`projects`: конфликт URL может привести к 404 или неверному шаблону.
- Шесть ключевых услуг — обычные страницы, а не записи `service`.
- Не удаляйте зарегистрированный CPT `service` или `single-service.php`, не выяснив, не начали ли они использоваться для дополнительных услуг.
- Перед удалением любого файла проверьте ссылки из `functions.php`, вызовы `get_template_part()`, подключение в enqueue и обращения к ресурсам из CSS/JavaScript.

### Иконки и материалы сайта-образца

В некоторых секциях исходного сайта SVG загружается динамически и не виден в исходном HTML. При необходимости сравнивайте живой DOM через DevTools. При копировании SVG удаляйте ненужные атрибуты и проверяйте, что цвет и размеры управляются ожидаемыми CSS-правилами. В ряде иконок используется `stroke="currentColor"`, а цвет задаётся из CSS.

## Проверка после изменений

Перед фиксацией существенных изменений проверьте:

### 1. PHP

Если PHP доступен в окружении разработки, запустите проверку синтаксиса для изменённых файлов:

```bash
php -l functions.php
php -l inc/cpt.php
php -l page-production.php
```

Команду `php -l` повторите для каждого изменённого PHP-файла. Это быстрая проверка синтаксиса, но она не заменяет тестирование в WordPress.

### 2. Основные URL

Проверьте главную страницу, страницы компании и контактов, все шесть страниц услуг, политику конфиденциальности, архивы сертификатов и отзывов, список проектов, каждую категорию и несколько детальных проектов. Отдельно откройте несуществующий адрес и убедитесь, что работает `404.php`.

### 3. Адаптивность

Проверьте широкую десктопную ширину, планшет и мобильные размеры. Особое внимание уделите меню-бургеру, длинным заголовкам страниц услуг, сеткам карточек, галереям, форме заявки, карте и подвалу.

### 4. JavaScript и внешние зависимости

В DevTools проверьте вкладки **Console** и **Network**: отсутствие ошибок, успешную загрузку CSS/JS/CDN и работоспособность модалки, лайтбокса и карты. Проверяйте мобильное меню в связке `header.php` + `main.css`/`responsive.css` + `main.js`.

### 5. Контактная форма

Проведите end-to-end проверку, описанную в разделе [«Форма и модальное окно заявки»](#форма-и-модальное-окно-заявки), включая фактическое получение письма. Нельзя считать доставку подтверждённой только по отображению сообщения об успешной отправке в браузере.

### 6. Постоянные ссылки

Если изменялись CPT или таксономии, сохраните настройки постоянных ссылок. Если отдельная страница или архив после этого возвращает 404, проверьте слаг страницы, регистрацию типа записи и rewrite-правила.

## Известные ограничения и задачи перед релизом

По текущему хендоверу разработка основных страниц завершена. Перед переносом на боевой сайт остаются следующие пункты:

1. Проверить и при необходимости пересоздать битые пункты меню — особенно ссылки на услуги в шапке и подвале.
2. Провести заключительный мобильный проход по всем шести страницам услуг.
3. Выполнить end-to-end проверку AJAX-формы и доставки писем на целевом хостинге.
4. Добавить/проверить SEO title, description и Open Graph — решение о SEO-плагине или кастомных полях пока не зафиксировано.
5. Рассмотреть оптимизацию загрузки: preload шрифта, lazy loading карты и `defer` для основного JS, проверив при этом отсутствие регрессий.
6. Провести кросс-браузерную проверку.
7. По плану постепенного улучшения перевести статические изображения сертификатов, отзывов и часть галерей в медиатеку WordPress.
8. Проверить содержимое CPT `certificate` и `opinion`, а также файловые фолбэки изображений на целевом сайте.
9. Проверить координаты/маркер карты на `/contacts/`.
10. Очистить оставшиеся неиспользуемые CSS-селекторы после изменений модального окна и отдельных страниц.
11. Проверить старый sitemap перед запуском и при необходимости настроить точечные 301-редиректы со старых URL объектов на новые `/project/<slug>/`.
12. Проверить все контакты, фото директора, настройки WordPress и ссылки после переноса.

Некоторые изображения в текущей теме пока хранятся в `assets/images/`, а не в медиатеке. Это намеренный существующий паттерн для ряда блоков и фолбэков; не удаляйте такие файлы без переноса их использования.

## Резервное копирование и перенос на боевой сайт

Перед обновлением или заменой темы создайте резервные копии как минимум:

- базы данных WordPress;
- каталога `wp-content/uploads/`;
- текущего каталога темы;
